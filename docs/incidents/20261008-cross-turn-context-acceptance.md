## 已确认的断点与候选范围

- Agent `domain/agent/turn.py::_publish_memory_observation` 发布当前用户原文；`domain/history/fanout.py` 构造的 `ConversationTurnPayload` 没有前文。Memory `_render_user_prompt` 只读取当前 `[USER]`，不读取助手回答。
- 原文所有权在 Agent。已有 `AgentConversationReader.list_turns_for_conversation` 按 Owner/伙伴校验 conversation，再由 `list_for_turns` 读取消息。每轮持久化 metadata 带 session/Realm；不能使用 conversation 当前身份的回退值推断历史轮身份。
- 候选复用上述 reader、事件和抽取账本，限制六轮用户原文，每轮最多 4000 字符；跨 conversation/session/Owner/伙伴/Realm、未来轮、重复轮拒绝。遇到私密或缺失轮停止向前读取，不跨越缺口；助手回答不提供给抽取器。
- 新增的依赖轮次只存于已有 decision JSON，不新增历史库。候选包含同策略重放、前文删除后拒绝重抽取、跨版本 tombstone、依赖事实删除的验证。候选协议为 `atomic-claims-v3-context`，旧无上下文事件的 input hash 保持不变。
- 这些机制只解决输入来源和生命周期，不能证明模型已正确识别指代。不能用边界单测替代语义反例。

## 后续复盘修正与本轮目标收敛（2026-10-08）

本节落实后续“修正复盘、推进目标收敛”的要求，调整后续工作范围，不改写上面的实验结果。

### 对前次复盘的修正

1. **失败结论限于已测试候选。** 前文传递和已有账本复用本身未被证明不可行；已证实的是，这一候选的模型判断仍不满足缺主语不写的门禁。证据不足以断言必须重构或换模型。`son owns 小狗` 按本轮策略属于不可接受的泛化写入；它与“擅自把小狗绑定成铁锤”是不同错误，不能混为一谈。
2. **开发顺序需要调整，生命周期要求不能省略。** 应先用最小输入切片核对语义边界和标注，再接通跨组件事件。删除、重放、隔离本来就是上下文功能的必要依赖，不应因为收敛而删掉这些要求。上一轮在语义门禁未通过前展开这些实现，投入顺序不合理；撤回合理。
3. **避免扩大当前能力承诺。** “完整表达的事实能够可靠保存、召回”和“系统不会把投递成功当成记住”是产品目标，不是已有少量样本足以证明的结论。保留已验证的具体修复和用例，不承诺所有完整陈述、所有召回或所有回答均正确。
4. **三项时效不是串行三段。** Agent 在回答前调度 Memory observation/outbox，持久会话原文则在 turn 的 finally 中异步保存；原文与语义投影没有已证明的固定先后顺序。应按同一 turn_id 分别记录明示起止点，禁止相加或拿一项代替另一项。
5. **不为文档收尾再跑全部矩阵。** 生产代码撤回后与既有部署修复一致，既有真实验收仍可引用。只补撤回后的代表性协议 E2E，不重跑性能、真实模型抽取或全量测试来堆积记录。
