# 抽取层的架构级修复方案（待 review）

写于 2026-08-09。依据是 `reports/memory_quality_20260809_082825` 这一次 90 轮实测，
文中每个数字和每个实体 id 都是从那次运行的图里读出来的，不是举例。

---

## 一句话根因

**抽取器是一个无状态的、逐轮的 LLM 调用，却被要求产出全局一致的标识符、并识别"这条事实
取代了哪条旧事实"——而这两件事都取决于它从未被给看的那张图。**

其余全部现象都是这一条的推论。特别地：**这次的错误输出几乎全部是 prompt-compliant 的**，
所以"把 prompt 写得更严"不是方案。

- 第 2 轮"我妈张丽" → `mother:张丽`。第 28 轮"我妈搬家了"没提名字，按 prompt
  第 79 行的规则，`mother` **就是正确答案**。两个 id 都对，指的是同一个人。
- `self -[attended]-> 送铁锤到_mother_处` 不是模型走神，它照抄的是 prompt 第 106 行
  的示例 `{subject:"self", predicate:"attended", object:"陪 mother 去医院"}`。
- 要模型在第 28 轮说出"这取代了 `mother lives_in 西湖区`"，它必须知道那条三元组存在。
  它不知道。prompt 里所有 invalidation 示例都是**同一轮内的显式否定**（"我现在不喝咖啡
  了"），那种情况旧事实在原文里被重述了，所以无状态也能做。

---

## 实测出来的三个后果

### 后果一：实体表里 60% 不是实体

89 个 `entity_id`，人工分类后约 35 个是真实体，其余是事件/状态短语被建成了节点：

```
送铁锤到_mother_处          帮_person:小林_兜底未交付的任务
每天早上过一遍_op-3091_进度    入住祇园附近旅馆且步行可达清水寺
make_and_send_osmanthus_lotus_root_annually
日本旅行（京都4天、大阪2天）   西湖区房产挂牌出售中
```

**关系被编码进了节点名。** `送铁锤到_mother_处` 本该是一条边
`self -[gave]-> pet:铁锤`，现在"送"和"给谁"都埋在字符串里，图无法沿着它走。

`kg_entities.entity_type` 这一列存在、schema 里有默认值 `'unknown'`，
**89 个实体全部是 `unknown`**——从来没有任何代码写过它。

### 后果二：同一个东西有多个 id

从这次的实体表里直接读出来的：

| 同一个所指 | 图里的 id |
|---|---|
| 妈妈 | `mother`、`mother:张丽` |
| 爸爸 | `father`、`father:李国强` |
| 妹妹 | `sister`、`sister:李婷` |
| 陈昊的女儿 | `person:念念`、`person:陈昊之女` |
| 星槎项目 | `project:星槎`、`project:星槎项目`、`星槎项目负责人`、`project:星槎_第一版交付` |
| OP-3091 | `project:op-3091`、`op-3091_的负责人`、`closely_monitoring_op-3091`、`每天早上过一遍_op-3091_进度` |
| 出版社 | `place:出版社`、`publishing_house` |
| 恒维医疗 | `company:恒维医疗`、`medical_device_company` |
| 睡不好 | `insomnia`、`poor_sleep`、`sleep_issue` |

最后四行还暴露了一件独立的事：**模型会把对象翻译成英文**，而且不稳定——米氮平写成
`mirtazapine`、合唱团写成 `choir`、桂花糖藕写成
`make_and_send_osmanthus_lotus_root_annually`。所以有用的边挂在 `mother` 上，
而 `mother:张丽` 只有一条 `has_state -> insomnia`。

### 后果三：没有任何东西被"取代"

12 道多跳题的失败分布：**7 题端点实体图里不存在，4 题两端都在但无边相连，1 题
（hop-008）通过了但那道题是我出错了**——查询里写了"我妈"，也就是桥接实体本身，退化成
单跳。**没有一道题在图里存在真正的两跳路径**，所以"图能不能遍历"这次根本没被测到。

6 道失效题里 5 道把当前事实答对了，全部只因为旧事实一起回来而判错。逐条查图：

| 旧 → 新 | 图里的旧值 | 图里的新值 |
|---|---|---|
| 西湖区 → 滨江区 | 只有 `self has_state 西湖区房产挂牌出售中`（事件短语） | `mother lives_in place:滨江区` |
| 舍曲林 → 米氮平 | **没有** | `mother takes_medication mirtazapine` |
| 急诊 → 内科 | **没有** | `person:王芳 works_at place:内科` |
| 实习生 → 转正 | **没有** | `person:小林 achieved 转正` |
| OP-3091 → 星槎 | `person:李总 holds_role op-3091_的负责人` | `person:李总 holds_role 星槎项目负责人` |
| 六月底 → 两周 | `self has_concern 六月底出第一版` | **没有** |

**六次违规全部是 `VIOLATE-vec:`。** 旧文本来自抽屉库而不是图——去 chroma 里查，
"她退休两年了，一直住杭州西湖区那套老房子"、"开了舍曲林，先吃三个月"都还活着，没被归档。

这一点决定了方案的重心：**失效的主战场在抽屉侧，不在图侧。** 只修图的方案在这六道题上
得零分。

## 方案：分层，且尽量不靠 LLM

排序原则：**能用确定性规则解决的，不要交给模型。** 模型只用在确定性规则原理上做不到的
地方。

### L0 — 先给"实体"一个可判定的定义

没有这条，后面每一层都无法强制。提议的判据：

> 一个东西是**实体**，当且仅当它在时间上可以作为多条陈述的主语，且其身份不依附于任何
> 单个事件。其余是**值**（状态/概念，如 insomnia）或**事件**（一次发生）。

对应三种三元组形状：

| 形状 | 例子 | 进不进遍历图 |
|---|---|---|
| `实体 -p-> 实体` | `mother lives_in place:滨江区` | **进**，这是边 |
| `实体 -p-> 值` | `mother has_state insomnia` | 不进，但可查 |
| `实体 -p-> 事件` | `self attended 送铁锤到_mother_处` | 不进 |

把 `entity_type` 这一列真正用起来（今天 100% 是 `unknown`）。

### L1 — 写入边界做类型强制（确定性）

`add_triple` 判定 object 是不是实体引用：形如 `role`、`role:name`、`type:name`，
或者已经是已知实体。自由短语一律判为值/事件，**不进 `kg_entities`**。

- 效果：89 个实体收敛到约 35 个，连通性才开始有意义。
- 代价：图里查不到"我某天做了什么"。这类内容本来就同时写进了 fragment，不丢。
- 风险：判据太严会把真实体（如 `云舟科技`，没有前缀）挡在外面。需要一条兜底：
  turn 内被 `mentions` 指认过的名字视为实体。

### L2 — 身份归一（确定性 + 账本）

prompt 定义的 `role` / `role:name` 约定本身是机器可判的：`mother` 与 `mother:张丽`
共享角色。规则——**当一个角色下恰好只有一个具名实例时，二者是同一实体**，合并，以更具体
的 id 为规范 id，改写既有陈述。`father`/`sister` 同理。

- 需要一张规范 id 映射表（`kg_entity_mentions` 已经在了，可复用），合并要可逆——
  直接改写陈述而不留映射，一旦合并错就无法回退。
- **它解决不了**：`念念`/`陈昊之女`、`place:出版社`/`publishing_house`。这两类要 L4。

### L3 — 功能性谓词自动关闭旧值（确定性）

声明一组**功能性谓词**（每个主语单值）：`lives_in`、`works_at`、`takes_medication`、
`holds_role`、`member_of`、`assigned_to`。写入新值时自动给旧值盖 `valid_to`。
不需要模型参与——而这正是无状态模型原理上做不到的那件事。

多值谓词（`likes`、`owns`）仍然需要显式 invalidation，那条路今天是通的。

**诚实的预期**：这次 6 道题里只有 1 道（OP-3091→星槎，`holds_role` 两个活值）会被它修好，
因为其余 5 道的旧值压根没进图。**L3 单独上，invalidation 从 0/6 到 1/6。**

### L3.5 — 抽屉侧的取代（失效题的真正主战场）

六次违规全部来自抽屉。三条路：

- **(a) 由 L3 的关闭连带归档抽屉**：`canonical_facts` 账本里已经有 `projection_id`，
  就是"该归档哪一条"的唯一线索，链路是现成的、有测试的，**缺的只是触发源**。
  但它只在旧事实曾被写成三元组时有效 → 这次 1/6。
- **(b) 让 steward 在写更新时同时发失效**：做不到，这就是根因本身。
- **(c) 抽取时给模型看旧抽屉**（= L4）：模型能指名它取代了什么。

→ 结论：**(a) 确定但覆盖窄，(c) 才是完整解。** 这是 LLM 上下文无法回避的一层。

### L4 — 抽取时把图喂给模型（最后一招，但对身份与取代都是唯一完整解）

调用前按本轮文本检索已有实体和相关事实，作为"已知实体 / 已知事实"放进 prompt。
模型于是能复用 id，也能指名它取代了什么。

- 代价：写路径上多一次检索（图查 3.8ms，向量一次）+ token。写路径当前约 45 秒/轮，
  瓶颈在模型本身，这点开销可忽略。
- 风险：**过度合并**——把两个同姓的人并成一个，比不合并更糟；以及锚定偏差，模型倾向于
  顺着已有事实说。需要在验收里专门放反例。
- **建议放在 L1–L3 之后再测是否还需要**，因为前三层是确定性的、便宜的，而且会显著缩小
  L4 要解决的问题面。

## 不做的事

1. **不放宽 benchmark 或语料。** 这次的守卫和断言都在正确工作，它们是这份诊断的来源。
2. **不把"prompt 写得更严"当方案。** 这次的输出几乎全部 prompt-compliant——第 28 轮
   没提名字时 `mother` 就是 prompt 规定的答案，事件当 object 是 prompt 第 106 行的示例。
   要求模型更小心，等于要求它知道它看不到的东西。prompt 该改的是**删掉那条教坏的示例**
   （L1 的配套），不是加更多告诫。
3. **不动读路径。** 这次的证据全部指向写入侧。读路径 p95 97.9ms，没有问题。

## 验收标准（先定，再动手）

| 指标 | 今天 | 目标 |
|---|---|---|
| `multi_hop` | 1/12（且那 1 道是坏题） | ≥ 8/12 |
| `invalidation` | 0/6 | ≥ 5/6 |
| 实体表中事件短语占比 | ~60% | < 10% |
| 同一人的 id 数 | 2（mother / mother:张丽） | 1 |
| 存在真实两跳路径的多跳题 | 0/12 | 12/12 |

最后一行是先决条件：**在图里没有路径之前，谈遍历没有意义。**

顺带要修的坏题：`hop-008` 在查询里写了桥接实体"我妈"，退化成单跳。语料校验器目前
不检查这一点，应当补一条断言：**多跳题的查询文本不得出现桥接实体的任何别名。**
