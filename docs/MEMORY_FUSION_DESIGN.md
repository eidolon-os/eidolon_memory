# 向量与图如何配合：eidolon memory 的完整设计（待 review）

写于 2026-08-09，取代 `KG_EXTRACTION_PROPOSAL.md` 里的方案部分（那份的**诊断**仍然有效，
方案是打补丁的思路）。依据是 `reports/memory_quality_20260809_082825` 那次 90 轮实测、
本仓库的代码、以及 Graphiti / Mem0 的公开实现。

---

## 一、第一性问题：两个存储各自负责什么？我们从来没定义过

今天抽屉库和图**由同一次 LLM 调用、从同一轮对话、抽出同一批内容**，只是形状不同。没有
分工声明，也没有任何东西把它们绑在一起。

实测的两个数字直接指向这件事：

| 证据 | 数字 | 说明什么 |
|---|---|---|
| 只有图命中、向量没命中的题 | **4 / 96** | 图基本是向量的**冗余副本**，不是补充 |
| 失效题里旧事实从哪回来的 | **6 / 6 来自抽屉** | 图知道新事实，但**管不住**抽屉 |

**所以缺陷不是"图不够强"，是两个存储重复且互不约束。** 我上一版按"把图做强"去设计，
方向就错了。

### 提议的分工

| | 抽屉（向量） | 图 |
|---|---|---|
| 存什么 | **情节**：谁在什么时候说了什么 | **当前状态**：现在什么是真的 |
| 语义 | 追加式，**永不为假，只会变旧** | 双时间投影，**可被取代** |
| 擅长 | 叙事、语气、情绪、"他当时怎么说的" | 身份、属性当前值、时间区间、枚举 |
| 回答 | 我最近心情怎么样 / 我们聊过什么 | 我妈现在住哪 / 我在做什么项目 |

这就是 event sourcing 的那条线：**抽屉是事件流，图是物化视图。** Graphiti 把两者压在
一个存储里（边自带 embedding），所以他们不需要这条分工；**我们本来就有两个存储，这条
分工是免费的——只是从来没有声明过。**

### 由此重新定义图的职责

**图的价值不是"回答向量答不了的问题"，而是"让向量的答案变得可信"。**

按这个尺度重新看 4/96：那不是图的失败，那是**用错了尺子**。真正该问的是"图有没有让向量
的答案变准"，而今天这个答案是 **0/6**。

多跳遍历随之**不是目标**。图是状态投影，不是寻路引擎。

## 二、唯一需要的绑定：时效（currency）

两个存储之间必须流动的只有一件事：

> **当图知道一条事实已被取代时，陈述旧事实的抽屉不能再被当作"现在"呈现。**

### 关键判断：不要归档旧抽屉

「她退休两年了，一直住杭州西湖区那套老房子」这条抽屉**不是假的**——她当时确实住在那里，
她确实说过这句话。假的是把它当成现在。

所以正确做法**不是删除或归档**（那会毁掉情节流，也毁掉"她三月搬的家"这个回答），而是
**标注**：召回时把图已取代的事实所对应的抽屉标成"曾经"。

一个陪伴体说「她以前住西湖区，2026 年 3 月搬到滨江区」，**比只说「滨江区」更好**。

**这条同时说明我自己的验收标准是错的**：`forbidden_contains: ["西湖区"]` 把上面那句好
回答判成违规。见第五节。

### 这条绑定的接缝已经存在

- 图的每条陈述带 `source_turn_id`
- 抽屉也带 `source_turn_id`
- `forget` 已经在用这条对应关系：`kg_sqlite.forget_source_turns()` ↔
  `forget.source_turns_for_drawers()`

**同一条接缝已经为"遗忘"承重。** 取代只是它的第二个用途，不需要新机制。

```
图判定某陈述被取代
  → 取该陈述的 source_turn_id
  → 反查这些 turn 产出的抽屉
  → 在召回结果里给它们打 superseded 标（不删、不归档）
```

## 三、写入侧：三件事

### W1 — 抽取只产出两类东西，且形状受约束

今天的 89 个"实体"里约 60% 是事件短语（`送铁锤到_mother_处`），
`kg_entities.entity_type` 100% 是 `unknown`（有这一列，从没有代码写过它）。

两条改动：

1. **prompt 的命名规则改成无条件可满足。** 今天是「提到名字就用 `mother:张丽`，
   否则用 `mother`」——同一个人两个 id，**两次都合规**，因为规则依赖"本轮是否恰好提到
   名字"这个偶然。改成无条件的一种形式即可。

   **不抄 Graphiti 的 possessor-qualified**（"Nisha's dad"）：他们的图里有很多说话人，
   裸的 "dad" 真有歧义；我们的 space 是 `(tenant, owner, companion)`，**一个 space 一个
   owner**，库里只有一个"妈妈"。照抄等于加一段我们不需要的消歧噪声。

2. **prompt 删掉那条把事件当 object 的示例**（第 106 行
   `{subject:"self", predicate:"attended", object:"陪 mother 去医院"}`），并加一张禁止
   清单：抽象概念与情绪、句子片段与从句、泛化裸名词不得成为实体。这张清单可以直接对着
   Graphiti 的 `extract_nodes.py` 抄——我们图里的污染物逐条命中它。

   事件不再进图，它们本来就同时写进了抽屉，**不丢**。

3. **写入边界兜底**：`add_triple` 落库前判断 object 是不是实体引用，自由短语判为值/事件，
   不进 `kg_entities`，并把 `entity_type` 真正写上。

   为什么 prompt 之外还要这一层：这次的坏输出**几乎全部是 prompt-compliant 的**，
   所以只靠 prompt 是把正确性押在模型的服从度上。

### W2 — 取代判定：检索候选 + 时间戳比较，不用 LLM

写入一条新陈述时，检索图里语义/结构相近的旧陈述作为候选，然后**纯时间戳判定**：
若候选的 `valid_from` 早于新陈述的 `valid_from`，把候选的 `valid_to` 设为新陈述的
`valid_from`。

这就是 Graphiti 的 `resolve_edge_contradictions()`，**零 LLM 调用**。

- **不做**第一版设想的手工功能性谓词表（`lives_in`/`works_at`/…）：要人维护且必然漏。
- **数据条件已满足**：这次运行 `valid_from` **76/76 全部填好**，且填的是语料真实时间
  （因为本次会话已修好 bench 认语料时间戳这件事）。

### W3 — 取代传导到抽屉

W2 判定的取代，走**已有的** `MemoryIntent` 路径。今天这条路径由
`decision.invalidations` 驱动，链路是：

```
turn_processor.py:447 → invalidate_exact_canonical_fact()
  → registration.projection_id → backend.get_by_source_turn_id() → 处理抽屉
```

**现成、接好、有测试。** W3 不是造新管道，是给它加一个触发源——并按第二节的判断，
把终点从"归档"改成"打 superseded 标"。

## 四、读取侧：把"现在"和"曾经"分开呈现

数据已经齐了，没有一个字段需要新增：

- 每条抽屉带 `memory_time`（`MemoryWireRecord`）
- 每条三元组带 `valid_from` / `valid_to` / `recorded_at`
- 渲染器已经会给三元组标 `（推测）` 和 `（根据 2026-03 的对话）`

缺的只有一件：**没有任何东西说"这条抽屉陈述的事实已经不是现在了"。**

### R1 — 召回结果分层

召回返回的记录增加一个 `superseded_by` 之类的标记（由第二节的接缝填），渲染时：

```
现在：她住滨江区（2026-03 起）
曾经：她一直住杭州西湖区那套老房子（2025-11，已于 2026-03 变更）
```

对 `eidolon_agent` 的契约影响：**只增字段，不改语义**，旧调用方忽略它即得到今天的行为。
这一点必须守住——契约稳定是本会话的既定约束。

## 五、验收标准（我的旧标准是错的，一并改）

| 指标 | 今天 | 目标 | 备注 |
|---|---|---|---|
| **时效清晰度** | 未测 | ≥ 5/6 | **新指标**，见下 |
| 实体表中事件短语占比 | ~60% | < 10% | W1 |
| 同一人的 id 数 | 2 | 1 | W1 |
| `multi_hop` | 1/12 | **不作为通过条件** | 图是状态投影，不是寻路引擎 |
| 召回 p95 | 97.9 ms | 不劣化 | W2 在写路径，不碰读 |

**"时效清晰度"取代原来的 `invalidation`。** 旧标准是
`forbidden_contains: ["西湖区"]`——旧事实出现即判错。按第二节的判断这是错的：
「她以前住西湖区，三月搬到滨江区」是更好的回答，却被判违规。

新判据应是：**召回上下文里，当前值存在，且旧值若出现则被明确标为过去。**
这需要改 `bench_memory_retrieve_quality` 的打分器——把
「旧值出现」从违规改成「旧值出现且未被标为过去」才算违规。

## 六、明确不做的事，及理由

| 不做 | 理由 |
|---|---|
| 实体去重的 LLM 步 | 图的独有贡献实测 4/96，撑不起一次额外 LLM 调用。W1 之后重测再议 |
| 多跳遍历 | 12 道多跳题是我自己出的，"送我铁锤的人现在住哪个区"不是陪伴产品里的说法。图定位为状态投影后，它不在目标内 |
| possessor-qualified 命名 | 他们多说话人，我们单 owner。抄过来是噪声 |
| 手工功能性谓词表 | 要人维护且必然漏，W2 的时间戳判定泛化 |
| 归档旧抽屉 | 抽屉不是假的，只是旧的。归档会毁掉情节流和"什么时候变的"这个回答 |
| 把图塞进抽取 prompt | 抽取 prompt 会无限膨胀，且有锚定偏差 |
| 动读路径的性能结构 | p95 97.9 ms，证据全部指向写入侧 |

## 七、顺序与可归因性

```
W1（prompt 两条 + 写入边界兜底）
   → 重测：污染物占比、id 数、时效清晰度
W2 + W3（时间戳取代 + 传导到抽屉）
   → 重测：时效清晰度
R1 + 打分器改判据
   → 重测：确认"曾经"被正确呈现而不是被抹掉
```

每一步之间都重测，是因为**这次会话已经证明"不重测就下结论"会连错四次**
（见 ARCHITECTURE「我在这上面连错了四次」）。W1 不写业务代码，是最便宜的一步，
也是唯一能让后面几步的效果可归因的前提。

## 八、这个设计解决不了什么（诚实边界）

1. **模型把对象翻译成英文**（米氮平→`mirtazapine`、合唱团→`choir`）造成的分裂，W1 的
   命名规则管不到，要靠 W1 的禁止清单收一部分，剩下的要 P2 的去重步。**本设计不解决它。**
2. **`person:念念` / `person:陈昊之女`** 这类同指不同名，同上。
3. **上游 500 且 `num_retries` 未设**——本会话两次实测中止里的第一次，是另一类问题，
   不在本设计范围。
4. **4/96 是在我设计的题目分布上测的**，换一种分布会更高。它足以支撑"先修时效、后议多跳"
   这个**顺序**，不足以支撑"图没用"这个**结论**。
