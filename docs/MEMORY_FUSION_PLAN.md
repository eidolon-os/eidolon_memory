# 向量 + 图：整合方案

写于 2026-08-07，供 review。

**标注约定**（沿用 `KG_REVIEW.md`）：带 ✅ 的是我读过源码或实际跑过确认的；外部结论标了来源；我在猜的地方写"我在猜"。

## 0. 一句话

**今天 eidolon_memory 里的向量和图是两个并排跑、各占一段 prompt 的系统，而不是一个记忆。** 把它们真正合成一个，是这个服务相对 MemPalace 唯一说得出口的技术理由——**因为 MemPalace 的图是一个默认没人往里写的旁路存储**（§1），所以"我们有图"本身不构成差异，"图真的参与记忆"才构成。

---

## 1. 先把前提钉死：MemPalace 在图这件事上给了什么

读的是本地装的 `mempalace 3.6.0` 源码。

| 检查 | 结果 |
|---|---|
| `knowledge_graph.py` 是否引用 palace / chroma / collection | **零** ✅ |
| 图文件默认路径 | `~/.mempalace/knowledge_graph.sqlite3`，**在 palace 目录之外** ✅ |
| 抽取管线（`convo_miner` / `general_extractor` / `dedup`）是否写图 | **零** ✅ |
| 谁写图 | **只有 MCP 工具 `kg_add`** ✅ |
| 谁读图 | 只有工具 `kg_query` + `fact_checker` ✅ |
| `searcher.py`（他们的检索）是否引用图 | **零** ✅ |
| `seed_from_entity_facts` 的调用者 | **零，死代码** ✅ |
| `source_drawer_id` | 是**工具调用方传进来的可选字符串**，不是系统维护的外键 ✅ |

**结论：他们提供的是一个图的"设施"，不是一个被填充、被使用的图。** 默认部署下它是空的。

所以本文档要回答的问题不是"怎么跟上 MemPalace"，而是"**在他们留空的地方，我们要建成什么样**"。

### 一个必须一起说的历史

自研图最早的第一条理由（`c90c08b`）是"多主机服务一个 space 时，图是唯一不能留在本地磁盘的部分"。`729ec17` 为此加了 PostgreSQL 图，`3fc70e0` 在 local-only 决定下删掉。**那条理由已经作废，但图的形状没有跟着重新推导过——本文档就是补这一步。**

剩下的理由依然成立且充分：`space_id`（多租户）、`audience` / `sensitive`（两层可见性）、时间戳写入归一（不毁索引）。**这三条和云无关。**

## 2. 设计哲学

每一条都挂在一个已验证的事实或一个硬约束上，不是口号。

### 2.1 一个记忆，两种形状

**向量存的是"说过什么"（原话、情节、有语气），图存的是"什么是真的"（推断、关系、有时效）。** 它们不是两个数据库，是同一份记忆的两个索引。

依据：两者的写入门是**独立的两道** ✅——fragment 看 `min_importance_to_write=3`，triple 看 `min_confidence_to_write=0.6`。这不是疏忽，是因为"值得作为一段记忆留着"和"是一条可靠的关系"是两个判断。一句 importance 2、confidence 0.9 的话**只该产生三元组**。

**推论**：任何试图让两道门一致的方案（"fragment 被丢就别写 triple"）都是在用能力换整齐，不做。

### 2.2 对外只有"记忆"

调用方不该知道这个部署有没有图。

依据：`RecallResult` 已经**故意**不带 `kg_triples`，理由写在 `memory_service.py` 里——"否则调用方能推断出这个部署有没有图"。

**但今天这条哲学是破的** ✅：它返回的 `context` 字符串里有一个段落标题就叫 `知识图谱事实`。**字段藏起来了，正文自己报了家门。** 契约和载荷互相矛盾，这是本方案要修的第一件事。

### 2.3 降级必须是渐变，不是掉块

依据：今天图超时 = `[MEMORY]` 里**整个消失一段带标题的内容** ✅，而且静默（`GRAPH_TIMEOUTS` 计数，不告诉任何人）。模型看到的不是"信息少了一点"，是"某一类信息不存在"。

**合成一个排名之后，图缺席就只是排序略差**——这才是"无感知"的真正含义：不只是外面看不出有图，而是**图掉线时不会塌一块**。

### 2.4 不能撒谎

伴侣答应忘掉一件事，就必须真的忘掉，或者说自己没做到。

依据：本 session 已修的两条（`ac71f00`、`55fe91b`）——遗忘曾经只删 drawer 留三元组，两条路径都是。**仍未修的**：`find_forget_candidates` 只扫 drawer，所以只存在于图里的事实遗忘不掉；`confirmation_required` 在用户那条路上被丢弃 ✅，"有歧义就问"从来没问过任何人。

### 2.5 在板子上成立才算成立

依据：本 session 首次在真 Pi 5 上测量，推翻了继承的 3–5x（实测 **2.3–2.7x**）✅，并测出图的墙在 **~14 万实体** ✅，以及一个只在真实规模下才暴露的写路径缺陷（28.44 → 1.00 ms）✅。

**任何本文档提出的效果，都必须在板子上复测。**

## 3. 产品逻辑：用户能感觉到什么

### 今天的实际行为（已验证）

图的种子只有两个来源，而且**二选一** ✅：

```python
if subject_names:                     # 调用方 focus_subjects 提示，会完全覆盖下面
    return kg.query_subjects(...)
if not entity_names:
    return []
return kg.query_entity_combined(...)  # 从「原始查询文本」匹配出的实体
```

**两条都不看向量结果。**

于是出现一个反向的失效：

| 用户说 | 文本里有实体名吗 | 图贡献 | 向量能不能自己搞定 |
|---|---|---|---|
| "张丽住哪儿" | 有 | 有 | **基本能** |
| "她住哪儿" | **没有** | **零** | 找得到记忆，但补不出关系 |
| "我上次说的那个事" | **没有** | **零** | 同上 |
| "他最近怎么样" | **没有** | **零** | 同上 |

**图在它最该补位的场景里沉默，在它最不被需要的场景里工作。**

### 目标行为

向量负责"找到相关的记忆"，图负责"把那些记忆里的**人和事**补全"：

```
用户："她最近怎么样"
  向量  → 找到 "上周妈妈说她腰不太好"
  图    → 从这条记忆的实体（妈妈）外扩一跳：
           妈妈 = 张丽 / 住在杭州 / 在医院工作 / 上个月做过体检
  合成  → 一个排好序的列表，没有出处标签
```

**这就是差异**：向量单独能回忆对话，加上图之后伴侣**认识人**。

## 4. 技术分层

现有分层（`domain/ → application/ → adapters/ + infrastructure/ → entrypoints/`）不用动。问题不在分层，**在于"这一轮该给模型什么记忆"这件事今天没有单一负责人**——它散在四个文件里：

```
public_recall.py    并行发起 + 决定预算
kg_recall.py        图查询 + 三元组渲染
recall_rerank.py    RRF（只在向量侧用）
recall_renderer.py  拼成 [MEMORY]
```

### 建议的形状：一条显式的检索管线，五个阶段

```
① 播种 Seed      这一轮是关于什么的
② 取候选 Gather  各来源并行取，各自有界
③ 外扩 Expand    从②找到的实体在图里走一跳
④ 融合 Fuse      一个排名（复用已有的 RRF）
⑤ 渲染 Render    一个列表进 [MEMORY]
```

关键变化是 ①↔② 之间从**并行**改成**级联**：

```
今天（并行）✅
    kg_task = create_task(图查询)          ← 种子来自查询文本，要扫全表
    向量检索
    await kg_task
    两段拼接

建议（级联）
    向量检索 + BM25 RRF          → 得到 top-K 记忆
    从 top-K 取 source_turn_id   → 图里索引查找，不扫描
    外扩一跳                      → 实体的其他有效事实
    全部进同一个 RRF
    渲染成一个列表
```

### 为什么级联反而可能更快（这条是论证，不是实测）

链路已经通了 ✅：MemPalace 3.5 的检索载荷会丢自定义 metadata，但我们已有 `_hydrate_hit_metadata` 用**一次批量 `get(ids=...)`** 补回来，所以**重排后的记录本来就带 `source_turn_id`**，而 `idx_kg_statements_source` 正好索引它。

于是从结果播种是：**精确**（不用模糊匹配，零假阳性）、**走索引**（查找而非扫描）、**热路径上零新增调用**。

而它顺带取消了 `match_entities_for_query` 在关键路径上的地位——**就是在板子上占越界时 96% 开销的那个线性扫描** ✅。

粗算（Pi 5，60k 陈述）：

| | 图这条腿 |
|---|---|
| 今天 | match 25.69 + combined 2.85 = **28.5 ms** ✅ |
| 级联后 | 索引查找 ≈ **3 ms**（外扩再加一次同量级查询） |

**串行化的代价是加上一个向量检索的时间，而省下的是 25 ms 的扫描。** 但——**Pi 上的向量检索延迟我没有测过**（板子上没装 chroma/onnx），所以这条是论证，必须实测验收。

### 文本匹配降级为兜底

`match_entities_for_query` 不删，改成**只在向量腿没返回任何结果时才跑**。那正是需要兜底的场景，而且很少发生。**扫描从"每次召回都跑"变成"罕见路径"，FTS5 的紧迫性随之下降。**

## 5. 计划

### 第一期：把两个系统合成一个排名（核心）

1. 检索管线显式化为五阶段，`public_recall` 只做编排
2. 种子加第三个来源：**重排结果 → `source_turn_id` → 三元组 → 实体**；三个来源取**并集**，`focus_subjects` 从"覆盖"改成"追加"
3. 外扩一跳，受 `kg_max_entities` / `kg_max_triples_per_entity` 约束（**这两个值的语义变了，要重定**）
4. 图的结果进入已有的 RRF，不再单独成段
5. 去掉 `知识图谱事实` 段落标题，三元组渲染成句子混进同一列表

**达到的效果**：§2.2 的契约和载荷不再矛盾；§2.3 的"掉块"变成"排序略差"；图开始在无实体名的查询上工作。

**怎么验收**：
- **49 题 dev 语料**（`ARCHITECTURE.md:266`，文档记录其运行间方差为零，可当门禁）——不升反降就是设计错了
- 在**板子上**跑端到端延迟，对 50 ms 语音预算
- 图掉线时 49 题的降幅（应该明显小于今天）

**风险**：外扩会放大进 prompt 的量；一跳的上限是判断不是测量（Graphiti 的 BFS 上限是 3 跳，但那是云上 Neo4j）。

### 第二期：让"忘掉"覆盖两个存储

1. `find_forget_candidates` 把三元组也纳入候选（用 `transcribe_triple` 渲染成文本，走**和 drawer 完全相同的**评分规则——那是纯子串包含，**没有阈值要标定** ✅）
2. `_apply_privacy` 不再丢弃 `PrivacyActionResult`
3. 抄 MemPalace 的 **`source_drawer_id`**：遗忘从"按轮次"变成"按事实"

**达到的效果**：§2.4 成立。

**未解决的、要单独决定的**：steward 那条路**没有嘴**（抽取在回复路径之外，22.9 s ✅），所以"有歧义就问"在用户侧无法实现。要么把只读的 `forget_preview` 放回 agent 面，要么让结果沿已有通道回到 agent（**后者要动 eidolon_agent，超出本仓**）。

### 第三期：按板子上的实测决定要不要继续

前两期做完，在板子上重跑 `probe_wall`。**如果 `match` 已不在关键路径，14 万实体的墙就不再是墙**，后面两件事都可以不做：

- **FTS5 trigram 索引**（两边都验证过可用 ✅：Mac 3.53.2 / Pi 3.46.1）
- **孤儿实体回收**（要两趟查询；显然的单趟 `NOT EXISTS` + `OR` 写法在 15 万条上跑了 13 分钟没返回 ✅）

**先测再决定，这是把它们排在后面的唯一理由。**

### 第四期：文档收敛

- `TEST_REPORT.md:276` 仍写 `KnowledgeGraphPort | Two implementations` ✅ —— 只有一个
- `ARCHITECTURE.md:82` 仍写他们"路径写死" ✅ —— **不成立**，`db_path` 是构造参数
- `KgConfig` 的 docstring 要说清楚：这个 port 服务的是**关闭开关、可测性、接口文档**，**不是**换 backend（`Literal["none","sqlite"]`，一个实现 ✅）

## 6. 明确不做

| 不做 | 为什么 |
|---|---|
| 把实体名做成 embedding 相似度匹配（Mem0 / Graphiti 的做法） | 他们把图命中当**排序信号**，一次假阳性只是排序差一点；**我们把三元组当断言渲染进 prompt**，一次假阳性是模型读到一条关于用户的假事实。短实体名的相似度噪声大，**用它做硬闸门和我们消费结果的方式不匹配** |
| 让两道写入门一致 | §2.1。用能力换整齐 |
| 按实体范围删除（遗忘） | "忘掉我妈住哪儿"会连"我妈叫张丽"一起删。伴侣记忆里过度遗忘不可逆 |
| 换图数据库 | 三个读已是常数时间，第四个是扫描不是查询，换存储不改变它的方向 |
| 图的 BFS 多跳 | 一跳都还没测过 |
| 退回用 MemPalace 的图 | §1：那里没有东西可退 |

## 7. 我在猜的，以及要你拍板的

**我在猜的：**

1. **Pi 上向量检索的延迟**——板子上没装 chroma/onnx，所以§4 的级联延迟论证**没有实测支撑**。这是第一期验收的第一件事。
2. **一跳是不是够**。Graphiti 用 3 跳，但那是云上 Neo4j。
3. **外扩之后 prompt 会大多少**，以及 `kg_max_entities=3` / `kg_max_triples_per_entity=8` 该改成什么。
4. **真实的实体:陈述比**。1.16 是 fixture 的最坏情况（宾语每条都不同），真实对话里宾语会重复。**这仍然要真实数据，而板子上还没部署 eidolon_memory** ✅（6 个服务里没有 memory，全盘找不到任何 palace，NATS `inactive`）。
5. **49 题语料对这个改动敏不敏感**。它 40 轮、35 个 fragment，可能测不出"图补全实体"的收益。如果不敏感，第一期就缺一个客观门禁——那要先承认，而不是拿一个不敏感的指标当通过。

**要你拍板的：**

1. **渲染层要不要保留"这是推断"的信号。** 契约层无感知是明确该做的（§2.2）。但三元组是 confidence 0.6 就写入的**推断**，向量片段是用户的**原话**。混进一个列表不加区分，模型分不出"你说过的"和"我们推断的"。可以不叫「知识图谱事实」（那是暴露架构），但可能需要别的措辞。
2. **`forget_preview` 要不要放回 agent 面**（只读，不含 `forget_confirm`）。这是唯一能在本仓内解决"steward 没有嘴"的办法，代价是 agent 面从 2 个工具变 3 个——而本 session 刚把它从 27 个砍到 2 个（3900 → 552 token）。
3. **部署 eidolon_memory 到板子的优先级。** 第三期和上面第 4 条都卡在这里。
