# Person 声纹与人脸档案

更新：2026-10-28。范围：用户档案管理；不新增人脸识别，不改变个人记忆的识别授权边界。

## 产品约束

每个 Owner 下的 Person 只对应一份当前有效声纹档案。档案可由多段录音建立；“一份档案”不等于只采集一段声音。Mobile 提供录入、重新录入、测试、删除，不再鼓励同一人建立多份档案。重新录入成功后替换；失败保留旧档案。并发录入按目标档案版本校验，过期请求不能覆盖新档案。

每个 Person 新增一份人脸档案，当前只管理一张参考照片。用户管理列表展示照片状态并提供入口，详情可查看、添加、更换、删除。明确显示“识别尚未启用”。停用 Person 仍可查看和删除照片，不能新增或更换。

照片保存成功不表示图片已通过人脸检测，也不表示 Person 已被识别。照片不得作为个人记忆访问凭据。实际声纹识别是否接受仍由识别服务决定；Memory 检查 Person、记忆开关和 Realm 权限。

## 数据和接口

Data 为声纹增加 `(owner_id, person_id)` 唯一约束，复用现有录入与评分流程。人脸采用独立 `person_face_profiles` 表，以 Person 为唯一主键并绑定 Owner。管理接口复用 Mobile → Admin Local API → Admin Management → Data 的认证链路；Owner 从认证上下文获取。

接口为 Person 下的 `face-profile`：GET 状态、PUT 替换、DELETE 删除；`face-profile/image` GET 读取图片。写请求必须携带 `expected_revision`，版本冲突返回 409。图片读取要求认证，并设置 `Cache-Control: no-store`。删除照片保留空档案版本，防止旧请求恢复已删除内容。

仅接受有大小与像素限制的 JPEG/PNG，服务端完整解码、校正方向、缩放并重新编码为 JPEG，去除原始元数据。使用现有对象存储，每次替换创建新对象，数据库提交后清理旧对象；数据库失败清理新对象。删除 Person 和 Owner 接入原有对象清理链路。

预留模型标识、预处理版本、特征结构版本与特征 JSON 字段。当前字段为空，识别状态固定为 `not_configured`，客户端不能提交识别特征。后续识别服务应以照片 revision 关联特征，拒绝为过期照片发布结果；照片替换或删除时清空旧特征。本轮不增加特征生成任务或识别开关。

## 旧声纹退役

按用户明确授权，旧声纹可删除并重新录制。`0013_person_biometrics` 对升级前的声纹、录音及录入任务直接清空，不再检查重复后要求人工挑选。已执行 0013 的 Host 由一次性 `0014_voice_enrollment_baseline` 清空同样的数据。人物、Realm、记忆和人脸档案不受影响。

在线录入完成流程要求新任务明确保存目标版本，不再给旧任务补默认版本。保留并发校验、失败保留当前有效档案以及模型特征一致性检查：这些约束服务于正常录入的正确性，并非旧数据兼容。历史迁移文件保留为数据库版本链记录，不新增旧结构的运行时读写路径。数据清空不会在每次启动执行，也无法通过 schema 降级恢复。
