# 用户生命周期与保留记忆管理

本方案替代旧界面中含糊的“删除用户 / 已删除用户 / 清空记忆”。

| 操作 | 人物资料 | 识别与记忆权限 | 后续操作 |
| --- | --- | --- | --- |
| 停用 | 保留资料、识别档案及记忆 | 停止人物参与识别和个人记忆读写 | 重新启用人物；个人记忆仍需按权威状态显式开启 |
| 归档 | 保留姓名、资料、归档时间和私人记忆；移除声纹、录音及人脸资料，确认框明确告知 | 人物与私人记忆均停用 | 查看详情、查看/导出/遗忘记忆、恢复归档、永久删除 |
| 恢复归档 | 归档资料回到用户列表 | 保持人物和记忆停用；不恢复生物识别档案 | 明确启用并重新录入识别档案 |
| 永久删除 | 清理私人记忆、待处理消息、账本、修复副本，移除 Person 和 Realm 记录及空目录 | 不允许恢复或重建原 Person ID | 成功后从列表消失；失败显示 pending 并可重试 |

## 身份资料缺失的历史记忆

0016 迁移产生的旧记录没有原姓名和人物资料。0017 明确标记 identity_state=missing，在独立的“身份资料缺失的保留记忆”区域展示，短编号仅用于区分记录，不代表姓名。详情解释来源、显示归档时间未知，并提供查看记忆和永久删除；前端不显示恢复按钮，后端同样拒绝恢复。不能靠占位姓名将未知身份恢复为真实用户。

## 删除协议

- 归档：POST /persons/{person_id}/archive，携带 expected_revision。原 DELETE 的软删除语义和旧 memory-purge 接口移除，不维护两套业务路径。
- 永久删除：POST /persons/{person_id}/permanent-delete，必须为已归档记录。身份缺失历史记忆也走同一流程。
- Data 在事务内登记删除回执，Realm 进入 deleting；完整目录仍持有它，但运行及管理访问关闭，只有明确 erasure_pending 才允许 Memory 清理。
- Admin 调用 Memory，经身份归属、维护锁和停止进程检查后清理该 Realm。只清理目标空间的 NATS 消息和消费者，既有其他用户、默认空间不受影响。
- Memory 成功后 Data 在同一事务删除 Person、Realm 并完成回执。跨服务中断时回执保持 pending，不能恢复，重试从同一意图继续。
- 完成回执仅保留 Owner/Person/Realm 的不透明标识、原始版本及完成状态，不保留姓名、个人资料或生物识别内容。用于响应丢失后的幂等重试和防止迟到的创建请求复活原身份，不是可恢复的用户归档。
- 历史对话与独立备份不属于这一操作的清理范围，永久删除确认框明确说明。回执和既有审计记录也不等于人物档案。
