# 混合片段保真试验：拒绝采用（2026-10-08）

结论：**不采用“模型声明片段独立即可双写”**。试验代码已撤回，生产仍为 6c27053。没有扩大召回或存储更多原文，也没有更改事实身份。

## 检查的问题和试案

当前 `turn_processor` 在同轮有 triple 时跳过全部 fragments。c-023 的 triple 及其证据只含家庭聚会，张丽/红烧肉仅在 fragment 中，故消失于可搜索投影。

试案给现有 StewardDecision 加 `independent_fragment_indexes`，只保存模型明确声明包含额外独立事实的片段。旧结果默认空列表，保留旧行为；索引经边界校验并随重要性/数量过滤重新映射；写入沿用 canonical ledger，无新表。提示词要求拆掉与 triples 重复的部分。实现保存在 `rejected.patch`，不是发布补丁。

## 对照证据

继续使用已授权的 c-001 / c-021 / c-023，旧、新提示词各两轮，第二轮倒置顺序。12 次调用全部完成，模型、temperature、提示词 SHA256 和解析后的决定见 `probe-results.json`。

- c-001：新版第一次仍把“母亲张丽失眠，持续一周”的重复片段声明为独立，虽然同轮已有 mother / has_state / 失眠。第二次没有额外片段。**1/2 出现重复事实独立存储的风险**。
- c-023：新版第一次只留下独立片段“张丽炖了红烧肉”；第二次却把“今天家庭聚会，张丽炖了红烧肉”整段标为独立，同轮另有 attended / 家庭聚会。**1/2 没有拆除重复部分**。
- c-021：片段和 triple 对心慌、乌龙茶的覆盖也有波动，不能把独立性标记视为可靠生命周期归属。

这些是开发样例，不是留出集。即使提示词直接包含 c-001 / c-023 示例仍出现问题，已经足够否决此试案，不能通过进一步调这个小样例的措辞宣布成功。

## 为什么撤回

保存额外信息的同时，重复片段会成为第二个可独立纠正的 assertion。纠正 triple 不会同步失效该片段。即使索引、幂等、删除流程的单元测试通过，也不能弥补模型错误归属。

试验还复现现有旧事件在 triple 已失效后重放会 NAK（reactivation intent id already belongs to canonical evidence），但不会复活；这在有无新标记两组都存在，不是本次改动引入。本轮不改变这项既有重放策略。

## 下一步的实现约束

继续同一问题，不启动路由、查询改写或另一套原文库：

1. 优先检查能否复用 `MemoryIntent` 已有的 `raw_claim`、结构化三元组和现有 ledger，使同一命题的自然语言与结构化表达在抽取时就成为一个写入单元，而不是两个数组事后声明“独立”。
2. 同一命题只注册一个 assertion。投影可以有不同表达，纠正和遗忘必须沿该 assertion 一起生效；真正不同的命题分别注册。
3. 先完成 c-023 的保留、c-001 的无重复、混合偏好/事件的精确纠正与删除重放，再复测质量。若需要修改抽取契约，先限定在这条写入链，不建立通用事实依赖图。
